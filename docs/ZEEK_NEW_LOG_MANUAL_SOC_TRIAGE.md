# DA005 — Explicit SOC triage of verified NEW Zeek research candidates

This is an **offline, operator-triggered** bridge from the independently
SHA-256-pinned NEW-log prediction report to an **Unclassified manual SOC case**.
It is **not** an automatic alert pipeline, an attack verdict, a real-time
detector, or a claim that the lab was physically isolated. It does not use
ground-truth labels, network sockets or Red Team traffic.

## Required private evidence

Keep outside the public Git repository:

1. The original, authorized Zeek ASCII `conn.log` from a new capture.
2. The previously exported data-only Zeek research model JSON, with its
   **independently recorded** SHA-256.
3. The original capture's **independently recorded** SHA-256.
4. The `new-predictions.json` generated by
   `scripts/score_zeek_new_log.py`, in the same private directory as
   `conn.log`.
5. A private lab notebook with the real VMware Host-only subnet, isolation
   checks, authorized scenario notes, Zeek version, and proof that this capture
   is not part of TRAIN, VALIDATION or reserved TEST.

Use Python 3.12.9 and dependencies installed per README. The tool first
recomputes and compares **every** saved prediction against the pinned model
and original capture, including source endpoints, timestamps and probabilities.
It rejects modified/oversized reports and out-of-scope IPs.

## Step 1 — Read-only list of eligible research candidates

From the repository root in PowerShell:

```powershell
py -3.12 scripts/triage_zeek_new_log.py `
  --model "C:/DA005-private/zeek-experiment/zeek-research-model.json" `
  --expected-model-sha256 "<independently recorded 64 lowercase hex>" `
  --log "C:/DA005-private/new-capture/conn.log" `
  --expected-log-sha256 "<independently recorded 64 lowercase hex>" `
  --report "C:/DA005-private/new-capture/new-predictions.json" `
  --cidr "192.168.56.0/24" `
  --list-candidates
```

The subnet is illustrative; replace it with the **actual** authorized RFC1918
VMware Host-only network. Repeat `--cidr` for up to four approved ranges.
The command lists **zero-based record indices** and research probabilities for
candidate flows among the first 500 rows only. It never writes SQLite. The
console listing intentionally omits private UIDs and IPs.

## Step 2 — Explicitly create or reuse one research case

After independently inspecting the original log and lab notebook, replace the
read-only `--list-candidates` option with:

```powershell
  --record-index 1 `
  --db "C:/DA005-private/soc/cyber_lab_cases.sqlite3" `
  --confirm-reviewed `
  --confirm-authorized `
  --confirm-new-capture
```

Append these options to the same model/log/report/CIDR arguments from Step 1.
Create the private `soc` directory first; the tool creates the SQLite file
if needed. Use an index actually listed in Step 1. These flags mean the
operator **attests** that they inspected the evidence, are authorized, and
checked that the capture is outside all three research partitions. The
software **cannot independently verify** these attestations.

The case is stored with verdict `Unclassified`, confidence `NULL`, and
state `New`. Its initial audit note records source, model, report and CIDR
digests, original Zeek UID, research probability and validation threshold,
plus explicit scientific limitations. The case is created only after the
original report is reverified **at write time**. Repeated requests for the
same source SHA-256 + UID reuse the existing research case and initial audit,
including requests concurrent with other analyst sessions. Manual cases
created through the legacy Cyber Lab interface are unaffected.

The `--db` destination must be a private `.sqlite3` file outside the Git
repository; no tracked dataset, model or existing database is deleted. Use
`src/siem_ai/case_report.py` / existing SOC case tools to inspect case history
as appropriate. A case is a **manual review record**, not a verified alert.

## Acceptance and limits

```powershell
py -3.12 -m pytest -q tests/test_zeek_new_log_triage.py
```

Synthetic tests exercise complete report recomputation, consent failures,
source/model hash failures, CIDR scope, report tampering, read-only listing,
SQLite idempotency and concurrency. GitHub CI is **not** a student laptop
experiment. A pinned SHA-256 proves only byte consistency with a separately
recorded reference, not model authorship or accuracy. CIDR checks cannot prove
physical Host-only isolation. No genuine independently labeled VMware
evaluation, detection latency, FPR/Recall, or operational AI alert is claimed.
Do not upload private log/model/report/database to GitHub or tune on TEST.

## Optional pinned TRAIN/VALIDATION/TEST partition gate

For a stronger **software-enforced exact-byte non-reuse check**, append the
following pair to **both** the listing and manual case commands above:

```powershell
  --manifest "C:/DA005-private/zeek-experiment/manifest.json" `
  --expected-manifest-sha256 "<INDEPENDENTLY_RECORDED_MANIFEST_SHA256>"
```

The manifest must be the **unchanged original**, kept with every original
TRAIN, VALIDATION and TEST capture and annotation referenced by relative path.
The CLI checks its independently pinned SHA-256, loads and validates all
source bytes/UID labels, checks the declared CIDR on each capture, verifies
host-disjoint partitions and model-manifest TRAIN/VALIDATION linkage, then
refuses the new capture if its bytes equal any declared split (including TEST).
The same check is repeated **inside the manual case write path**. Either
missing flag, invalid input or mismatch fails closed before any SQLite write.
The legacy commands without this optional pair remain compatible and explicitly
report that declared TEST exclusion is **not** software-checked. An existing
idempotent case may be reused without rewriting its original audit note.

This is not proof of preregistration, true independent labels, flow-level
non-reuse after re-encoding, physical isolation, or detection accuracy. Keep
the explicit `--confirm-new-capture` attestation even with a passing gate;
its historical/semantic meaning is not established by a digest comparison.
No raw model, log, labels, manifest or SQLite files should be committed.
