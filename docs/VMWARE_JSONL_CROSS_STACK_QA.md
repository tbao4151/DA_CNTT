# DA005: Python → private JSONL → Chromium cross-stack QA

This test is intentionally **network-free**. It tests the real Python 3.12 CLI, private UTF-8 JSONL writer and the production Next.js local-file viewer against one coherent contract rather than comparing independent hard-coded mock payloads.

The test cases generated by `tests/emit_vmware_jsonl_browser_cases.py` are:

1. **Actual dry-run:** invokes the real stepwise CLI through the exclusive file writer with execution OFF. Requires no SSH or VMware.
2. **Simulated completed nine-stage flow:** invokes the real Python stepwise CLI and file writer while the network-stimulus, Zeek SSH/SCP, Blue bridge and sleeper are patched to allow **no actual network**. The Zeek log and matching records are controlled fixtures created in the private runner temp directory. A completed status here means *software pipeline only*.
3. **Refused execution:** runs the real CLI with an explicit `--execute` request but without `--operator-confirmed-hostonly`; no packet is sent and a refusal terminal JSONL is emitted.

`frontend/scripts/vmware-python-browser-e2e.mjs` opens all three produced UTF-8 files through the browser's normal file input on the production `/vmware-progress` page. It checks stage counts and provenance disclosures, verifies refusal fails closed, tampers with a claimed VMware isolation verification to ensure it is rejected, and ensures the browser makes no POST/PUT/PATCH/DELETE file uploads.

The workflow `.github/workflows/vmware-jsonl-cross-stack.yml` uses Python 3.12.9, Node 20, Next.js production build, headless Chrome and a private GitHub runner temporary folder outside the Git checkout. This QA does **not** validate VMware isolation, a real Zeek capture, a trained AI model, external generalization, real attacks, true positive rates, or One-Click dual-AI execution.

Reproduce in an isolated development environment by installing the repo requirements and locked frontend dependencies, choosing a **new empty folder outside Git** for the test data, and running the generator followed by the frontend and Chromium test. Never place the generated mocked log/receipt in a research report as physical VM evidence.

Before the academic report, the operator must still verify actual VMnet isolation, Windows route, Ubuntu NIC, Zeek interface, pinned SSH key, source log timestamps and PCAP provenance, and separately substantiate any verified attack labels or Blue inference results.
